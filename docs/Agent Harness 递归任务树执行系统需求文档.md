# Agent Harness 递归任务树执行系统需求文档

## 1. 项目背景

随着大模型能力的发展，Agent 已经可以完成代码开发、资料调研、任务执行等复杂工作。但目前主流 Agent 系统大多采用一次性任务规划或者动态任务列表生成的方式，将复杂目标拆分为多个子任务后执行。

这种方式在复杂项目场景中存在一定问题：

- 任务拆分结果缺少长期维护能力；
- 执行过程中产生的新需求难以准确归属；
- 子任务之间的信息传递缺少统一规范；
- 任务失败后难以快速定位和恢复；
- 项目整体执行过程缺少可视化和可追踪能力。

因此，本项目希望设计一种基于递归任务分解思想的 Agent Harness，使 Agent 在执行复杂任务时能够动态构建任务树，并通过父子任务之间的结构化通信，实现任务的持续演化和可追踪管理。

---

# 2. 项目目标

构建一个面向复杂任务执行的 Agent Harness Runtime，实现：

1. 支持复杂任务的递归拆解；
2. 动态生成和维护 Task Tree；
3. 支持父任务与子任务之间的信息反馈；
4. 支持任务状态追踪和历史回溯；
5. 支持不同任务搜索策略，例如 DFS、BFS 等；
6. 支持新需求动态挂载到已有任务结构中；
7. 为后续 Agent Review、恢复执行提供基础能力。

---

# 3. 核心设计理念

## 3.1 Agent 执行模型抽象

将传统程序控制结构映射到 Agent Runtime：

| 传统编程概念 | Agent Runtime |
| --- | --- |
| 顺序执行 | Workflow |
| 条件判断 | Router |
| 循环 | Agent Loop |
| 函数调用 | Tool / Skill |
| 递归 | Recursive Task Decomposition |

通过这些基础控制能力，使 Agent 具备类似程序执行流程的任务处理能力。

---

# 4. Task Tree 任务树设计

## 4.1 根节点设计

根节点代表一个完整项目或长期目标，而不是单个执行任务。

根节点负责维护：

- 项目目标；
- 全局上下文；
- 技术约束；
- 当前任务状态；
- 子任务索引；
- 项目级 Memory。

例如：

项目目标：

企业 AI 知识库系统

任务树：

- 用户系统
- 文档管理
- RAG 检索
- AI 助手
- 权限系统

---

## 4.2 子任务递归拆解

当 Agent 判断当前任务复杂度较高时，将任务拆分为多个子任务。

拆解过程：

大任务

↓

判断任务复杂度

↓

生成子任务

↓

子任务继续执行相同判断逻辑

↓

直到任务达到可执行粒度

最终形成动态任务树。

# 5. Task Node 设计

每个任务节点需要保存：

## 基础信息

- task_id
- parent_task_id
- task_name
- task_description
- task_type

## 执行状态

包括：

- pending
- running
- completed
- failed
- blocked

## 上下文信息

记录：

- 输入信息；
- 依赖任务；
- 当前任务目标；
- 相关历史记录。

## 执行结果

包括：

- 完成摘要；
- 产生的代码或文件变化；
- 测试结果；
- 关键决策；
- 风险信息。

---

# 6. 父子任务通信机制

子任务完成后，需要向父任务返回结构化结果。

返回内容包括：

## 任务状态

用于判断当前任务是否完成。

## 任务摘要

描述当前任务完成内容。

## 产出信息

记录：

- 修改文件；
- 新增模块；
- 生成结果；
- 测试情况。

## 关键决策

记录实现过程中的重要设计选择。

## 风险和依赖

帮助父任务调整后续执行策略。

父任务根据返回结果更新自身状态，并决定下一步：

- 继续拆解；
- 执行下一子任务；
- 进入 Review；
- 重新规划。

---

# 7. 新需求动态加入机制

系统需要支持执行过程中产生的新需求。

例如：

当前任务：

开发知识库系统

新增需求：

增加企业微信登录。

处理流程：

1. 判断该需求属于哪个项目；
2. 检索已有任务节点；
3. 根据任务描述、上下文、历史执行信息进行匹配；
4. 定位最合适的父节点；
5. 创建新的子任务。

如果无法匹配已有节点，则进入待处理任务区域，由 Agent 判断是否创建新的任务分支。

---

# 8. Task Routing 设计

Task Router 负责：

- 判断任务所属项目；
- 判断任务所属模块；
- 判断任务挂载位置；
- 判断是否需要创建新节点。

输入：

用户需求。

输出：

- 目标任务节点；
- 匹配置信度；
- 创建策略。

---

# 9. Search Strategy 设计

任务树的执行策略支持插件化。

包括：

## DFS 深度优先策略

优先深入解决一个任务。

适合：

- 编码任务；
- Bug 修复；
- 单模块开发。

## BFS 广度优先策略

优先展开同层任务。

适合：

- 项目规划；
- 架构设计。

未来支持：

- Best First Search；
- Beam Search；
- 自定义搜索策略。

---

# 10. Harness 架构定位

本系统属于 Agent Harness Runtime，而不是单一 Skill。

整体结构：

Harness Runtime

负责：

- Task Tree；
- Agent Loop；
- 状态管理；
- 任务调度；
- 上下文管理。

Skill：

负责具体领域能力：

- Coding Skill；
- Research Skill；
- Testing Skill。

Plugin：

负责扩展系统能力：

- Memory Plugin；
- Tool Plugin；
- Search Strategy Plugin；
- Model Plugin。

---

# 11. 项目价值

相比传统 Agent 任务规划方式，本系统具备：

1. 动态任务演化能力；
2. 完整任务执行轨迹；
3. 子任务独立管理能力；
4. 更好的代码 Review 能力；
5. 更强的问题定位和恢复能力。

最终目标是构建一个可扩展的 Agent Runtime，使复杂任务执行过程具备类似软件工程中的结构化管理能力。
